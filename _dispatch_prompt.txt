## Spec: Sandbox / project scaffolding

The harness can work in a workspace, but every new project means manually creating files. This adds project templates: pick a template + name + parent dir, harness scaffolds it, switches workspace to the new project.

### Scaffold module

New `src/aura_harness/scaffold/`:
- `templates.py` — template definitions as Python dicts (no external files, keep it simple)
- `bootstrap.py` — `scaffold(template_id, name, parent_dir) -> Path` function
- `__init__.py` — re-exports

Template definition shape:
```python
@dataclass(frozen=True)
class Template:
    id: str          # "blank", "python_cli"
    label: str       # "Blank workspace", "Python CLI"
    description: str
    files: dict[str, str]   # relative_path -> content; both can use {name} placeholder
```

Two templates:
1. `blank` — just `README.md` saying `# {name}\n\nAura LLM Harness workspace.\n`
2. `python_cli` — minimal Python CLI scaffold:
   - `pyproject.toml` with project metadata, `[project.scripts]` entry `{name} = "{name}.__main__:main"`
   - `src/{name}/__init__.py` (empty)
   - `src/{name}/__main__.py` — has `def main(): print("hello from {name}")` and the standard `if __name__ == "__main__": main()` block
   - `tests/test_smoke.py` — single trivial test that imports the package
   - `.gitignore` — standard Python (.venv, __pycache__, *.pyc, build/, dist/, *.egg-info, .pytest_cache, .coverage)
   - `README.md`

Expose templates via a registry list/dict so the UI can enumerate them.

`scaffold(template_id, name, parent_dir)` behavior:
- Validate name: only `[a-zA-Z0-9_-]+`, raise `ValueError` if not (use `re.fullmatch`). Reject empty.
- Compute `target = parent_dir / name`. If it already exists and is non-empty, raise `FileExistsError`.
- Create target dir.
- For each file in the template, substitute `{name}` in both the path and the content, create parent dirs, write file.
- Return the target path.

### UI changes

Add a "New" button in the sidebar header row, next to the `[...]` workspace picker. Clicking it opens a `ScaffoldDialog`.

`ScaffoldDialog` (new class in `main_window.py` is fine, or split to `ui/scaffold_dialog.py` — your call):
- Modal QDialog with a small form layout
- `QComboBox` populated with templates (display: `label` — `description`, data: `id`)
- `QLineEdit` for project name (placeholder: "my_project")
- `QLineEdit` for parent directory (default: parent of current workspace) + a `[...]` button to pick via QFileDialog.getExistingDirectory
- Create / Cancel buttons
- On Create: validate inputs; if invalid, show inline error label and don't close. If valid: call `scaffold(...)`, close, and have the caller switch the workspace to the new path.

After successful scaffold:
- The MainWindow switches the active workspace to the new project (same code path as the [...] picker uses).
- Sidebar refreshes.
- Append a muted line to the output: `"Scaffolded <template_label> at <path>"`.

If scaffold raises (FileExistsError, ValueError, OSError): show a QMessageBox.warning with the message, leave the dialog open.

### Standards
Type hints, module loggers, no new third-party deps, no new tests for this dispatch (smoke-launching is enough verification).

### Definition of done
- "New" button in the sidebar header opens the scaffold dialog
- Selecting "Python CLI", entering a name like `foo`, picking a parent dir, hitting Create → creates `<parent>/foo/` with the template files (pyproject, src/foo/, tests, gitignore, README) and switches the workspace to it
- Selecting "Blank workspace" creates a directory with just a README
- Invalid names are rejected cleanly
- Existing-non-empty target dir is rejected cleanly
- All existing tests still pass

Be methodical. Read what you need, make the change, stop. Match existing code style. Type hints everywhere.
