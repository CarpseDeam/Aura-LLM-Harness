Task: State schema — module skeleton and design doc

Project context: Aura LLM Harness. Previous dispatch added a Backend abstraction (`aura_harness/backend/`). This dispatch lays down the typed state schema that every Station will read from and write to. No Station code yet — just the types, a design doc, and one small piece of behavior (a `RepoMap` builder).

The shape

A new module `aura_harness/state/` containing frozen dataclasses. Every type is immutable. No methods beyond what `@dataclass(frozen=True)` gives you, with one exception (the repo-map builder, in its own file). Pure types module — consumers will read these in later dispatches.

Files

- `state/__init__.py` — re-exports every public type below.
- `state/types.py` — all the dataclasses listed below.
- `state/repo_map.py` — `build_repo_map(workspace_path: Path) -> RepoMap`. Walks the workspace with `ast`, produces a `RepoMap`.

Types (in `state/types.py`)

All are `@dataclass(frozen=True)`. Use tuples (not lists) for collection fields so the dataclasses stay hashable and clearly immutable.

```python
@dataclass(frozen=True)
class FileSymbols:
    path: Path
    symbols: tuple[str, ...]      # top-level def/class names
    imports: tuple[str, ...]      # module-level imported names

@dataclass(frozen=True)
class RepoMap:
    files: tuple[FileSymbols, ...]

@dataclass(frozen=True)
class TaskSpec:
    task_id: str
    description: str
    workspace_path: Path
    constraints: tuple[str, ...] = ()
    context_files: tuple[Path, ...] = ()
    repo_map: RepoMap | None = None

@dataclass(frozen=True)
class SliceContract:
    expected_symbols: tuple[str, ...] = ()
    forbidden_imports: tuple[str, ...] = ()

@dataclass(frozen=True)
class Slice:
    slice_id: str
    description: str
    target_files: tuple[Path, ...]
    depends_on: tuple[str, ...] = ()
    contract: SliceContract = SliceContract()
```

Plan, CodeArtifact, CritiqueReport carry genealogy fields. The pattern is: every produced thing knows what station and backend made it, when, with what seed, and what state element it consumed (`input_ref`).

```python
@dataclass(frozen=True)
class Plan:
    plan_id: str
    slices: tuple[Slice, ...]
    rationale: str
    # genealogy
    produced_by_station: str
    produced_by_backend: str
    produced_at: datetime
    seed: int | None
    input_ref: str   # task_id

@dataclass(frozen=True)
class FileWrite:
    path: Path
    content: str

@dataclass(frozen=True)
class CodeArtifact:
    artifact_id: str
    slice_id: str
    files: tuple[FileWrite, ...]
    parent_artifact_ids: tuple[str, ...]   # () for round 0; (prior_id,) for critic retry; (slice0, slice1, ...) for integration
    critic_round: int                      # 0 for first attempt
    # genealogy
    produced_by_station: str
    produced_by_backend: str
    produced_at: datetime
    seed: int | None
    input_ref: str   # plan_id

@dataclass(frozen=True)
class CritiqueReport:
    critique_id: str
    artifact_id: str
    passed: bool
    violations: tuple[str, ...]
    suggestions: tuple[str, ...]
    # genealogy
    produced_by_station: str
    produced_by_backend: str
    produced_at: datetime
    seed: int | None
    input_ref: str   # artifact_id (matches `artifact_id` above; redundant but consistent with the genealogy pattern)

@dataclass(frozen=True)
class RunState:
    run_id: str
    task: TaskSpec
    plan: Plan | None = None
    artifacts: tuple[CodeArtifact, ...] = ()
    critiques: tuple[CritiqueReport, ...] = ()
```

repo_map.py

Single function: `build_repo_map(workspace_path: Path) -> RepoMap`.

Behavior:
- Walk `workspace_path` recursively, collect every `.py` file. Skip hidden directories (anything starting with `.`), `__pycache__`, `.venv`, `node_modules`, `.git`.
- For each file, read it and run `ast.parse`. On `SyntaxError`, skip the file (it might be a partial work-in-progress); don't raise. Log a debug-level message.
- Top-level symbols: walk the module body, collect names of `FunctionDef`, `AsyncFunctionDef`, `ClassDef` nodes at module scope only (not nested).
- Imports: walk the module body, collect `Import` and `ImportFrom` nodes at module scope. For `Import`, the name is the imported module (`import foo.bar` → `"foo.bar"`). For `ImportFrom`, prefix with the module (`from foo import bar` → `"foo.bar"`; `from foo import bar, baz` → `"foo.bar"`, `"foo.baz"`). For relative imports (`from . import x`), use `.x` style — keep them in but mark them recognizable.
- Paths in `FileSymbols.path` are relative to `workspace_path` (use `Path.relative_to`).
- Sort `FileSymbols` by path so the output is deterministic. Sort `symbols` and `imports` within each file too.

Design doc

`docs/STATE_SCHEMA.md`. Prose, not just code dumps. Sections:

1. **Why this schema exists.** Two paragraphs: stations need a typed object to pass around; immutability + genealogy fields are what make it not a toy. State is what the architecture is built on.
2. **The types.** One subsection per type. For each: what it represents, what produces it, what consumes it, and a short fenced code block showing the dataclass. Don't repeat the full code from `types.py` — just the field list and comments.
3. **Genealogy.** Why every produced thing carries `produced_by_station`, `produced_by_backend`, `produced_at`, `seed`, `input_ref`. A worked example: trace a single CritiqueReport back to its CodeArtifact back to its Plan back to its TaskSpec.
4. **The `parent_artifact_ids` pattern.** Why it's a tuple. Three cases — round 0 (empty), critic retry (one parent), integration (many parents). Tiny ASCII diagram if it helps.
5. **What's deferred.** Note that `prompt_version` was considered and punted; will be added when prompt regression tracking earns its place. Same for `IntegrationReport` as a separate type — currently folded into `CodeArtifact` via `parent_artifact_ids`.
6. **The repo map.** What it is, what fills it (`build_repo_map`), what reads it (the planner, eventually). Why AST and not tree-sitter for now (multi-language support is a future concern; AST is stdlib and enough for Python).
