aura_harness/pipeline/orchestrator.py

Pipeline class. Constructor:
- planner: PlannerStation
- executor: LinearExecutor
- integrator: IntegratorStation

Signature:
- run(task_spec: TaskSpec, workspace_path: str) -> RunState

Internal flow:
1. Build initial RunState from task_spec.
2. Call planner.run(task_spec) → Plan. Append plan to state.
3. Call executor.run(state_with_plan, plan) → RunState with artifacts. The executor runs each slice's worker (with internal critic loop). If a worker exhausts critic rounds without passing, it still returns the last CodeArtifact — that's existing behavior from dispatch 3, don't change it. The pipeline does NOT bail early on worker failures; we want maximum information per run, so all slices get attempted regardless of individual outcomes.
4. Call integrator.run(plan, state.artifacts, workspace_path) → IntegrationResult. Append to state.
5. Return final state.

If planner.run raises BackendError, let it propagate — there's no recovery and the user needs to see it. Don't wrap in try/except. Same for executor.run if it raises (shouldn't, but if it does, propagate). Integrator.run never raises by design; it returns IntegrationResult with success=False on any failure.

aura_harness/__main__.py — top-level CLI entrypoint

`python -m aura_harness --task-file <path> --workspace <path> [options]` runs the full pipeline.

Required args:
- --task-file: path to a TaskSpec spec file (matches the planner_smoke.py format from dispatch 5 — same pygame_smallgame/spec.md should work as input)
- --workspace: directory to write integrated code and the run record. Created if missing.

Optional args (with defaults):
- --planner-backend {cloud,local}: default cloud
- --planner-model: default deepseek-v4-flash
- --worker-backend {local,cloud}: default local. (Cloud workers are possible but expensive; default local is the thesis.)
- --worker-model: default whatever dispatch 3's pipeline/__main__.py defaults to for qwen2.5-coder — match it. If no default is set there, use qwen2.5-coder:14b (strongest local fast worker per the project notes).
- --critic-model: default whatever dispatch 3 used for the critic. Match it; don't introduce a new default.
- --critic-rounds: default 2
- -n / --candidates: default 3

For cloud backends, read DEEPSEEK_API_KEY from env. If a cloud backend is selected and the key is missing, exit with a clear error message before any work starts.

Construction order in main():
1. Parse args.
2. Build planner_backend (CloudHTTPBackend with DEEPSEEK_BASE_URL, or LocalOllamaBackend).
3. Build worker_backend similarly.
4. Build CriticClient with critic-model and worker_backend (the critic runs on the same backend as the worker — single-process resource considerations).
5. Build CriticStation, CandidateGenerator, WorkerStation, IntegratorStation, PlannerStation. Wire them.
6. Build LinearExecutor with the worker station.
7. Build Pipeline. Run it.
8. Write the run record (see below). Print summary.

Run record

After pipeline completion, write a `run_record.json` file at the workspace root containing a JSON serialization of the final RunState. Use a small helper to serialize: dataclasses.asdict for the state, datetime → ISO string, tuples → lists, omit any fields that aren't JSON-serializable (e.g. CompletionResult.raw might contain provider-specific objects — drop the raw field during serialization). The goal is enough information to reconstruct what happened: task, plan, slice contracts, per-artifact code, critique reports, integration result, all genealogy. Pretty-print with indent=2.

Console output during the run

Print as the pipeline progresses, not just at the end. Suggested shape (don't over-engineer the formatting; plain text lines with clear section markers are fine):
- "[planner] running on <backend>/<model>..." then on success "[planner] plan with N slices: <slice_id>, <slice_id>, ..."
- "[worker N/M] slice=<slice_id> target=<target_path>" before each slice, then "[worker N/M] done critic_rounds_used=K passed=<bool>" after.
- "[integrator] writing <count> files to <workspace>..." then "[integrator] success=<bool> compile_errors=<count>"
- "[done] run_record at <path>"

If the integration has compile_errors, print each one (file, line, type, message) at the end. The user is going to look at the workspace to evaluate quality, but compile errors should be visible without opening files.
