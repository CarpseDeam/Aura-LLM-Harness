## Goal
Replace binary pass/fail evaluation with a gradient (pass-count) signal, and use it to enforce monotonic improvement across critic rounds. Currently a critic round can produce code that passes fewer tests than the prior round, and the runner happily moves forward with worse code. We want a one-way ratchet: a retry only replaces the prior-best if it ratchets the pass-count forward.

## Verifier protocol change
Verify scripts under `bench/tasks/<task>/verify.py` currently exit 0/1. They will now also write a JSON report to a path passed as their third positional argument (the runner already passes a report path — see `_verify_candidate_round` in `runner.py`).

The report format:
```json
{
  "tests_passed": 7,
  "tests_total": 10,
  "failures": ["test name 1", "test name 2", "test name 3"]
}
```

The runner reads this report after the subprocess exits. If the report file is missing or malformed, fall back to the binary `returncode == 0` signal (treat pass as `tests_passed=1, tests_total=1`, fail as `0, 1`). This keeps the runner backward compatible with any verify scripts that haven't been updated.

Update `bench/tasks/duplicate_finder/verify.py` to emit this report. Decompose its current monolithic check into discrete named assertions — at minimum: "module imports", "produces output file", "output is valid JSON", "all paths are relative", "all paths use forward slashes", "duplicate groups are correct". Use whatever decomposition feels natural; the count matters more than the exact names.

The other four task folders (cron_parser, log_tailer, etc.) don't exist yet, so don't touch them.

## Data model changes
`RoundResult` (in `bench/models.py`) gains:
- `tests_passed: int`
- `tests_total: int`
- `failures: tuple[str, ...]`

The existing `passed: bool` field stays — it's `tests_passed == tests_total and tests_total > 0`.

`SessionSummary` gains aggregate gradient stats: `mean_tests_passed`, `mean_tests_total`. Compute across all final-round results (the round we kept per candidate).

JSONL session output naturally inherits these fields.

## Ratchet logic in `_resolve_candidate_slot`
Current behavior: each round generates a retry, and the next round's prompt uses the *most recent* round's code as `previous_code`. Failed retries replace the prior code in the prompt.

New behavior: track the **prior best** round (highest `tests_passed`, ties broken by most recent). The retry prompt always uses the prior-best's code as `previous_code` and the prior-best's critique. If a new retry's `tests_passed` is strictly greater than prior-best, it becomes the new prior-best. If equal or worse, it's logged in `rounds` but does NOT become the new prior-best — the next round retries against the same prior-best again with a fresh seed.

Termination conditions for the per-candidate loop (any of these stop it):
- Prior-best passes (`tests_passed == tests_total`).
- We've hit `critic_rounds` total retries (regardless of how many were ratchet-accepted).
- Critic returns no actionable violations.
- Code extraction fails on the prior-best (can't generate a follow-up prompt).

The candidate's final `passed` field is whether the prior-best passed. All rounds (including rejected retries) are kept in `rounds` for inspection — so the JSONL still has every attempt, with the rejected ones flagged.

Add a new field on `RoundResult`: `ratchet_accepted: bool` — true for round 0 and for any retry that strictly improved on prior-best.

## Test fallback for backward compat
If a verify script doesn't emit a report file (older tasks, or a crash before report write), the runner synthesizes:
- pass: `tests_passed=1, tests_total=1, failures=()`
- fail: `tests_passed=0, tests_total=1, failures=("verify exited non-zero",)`

This keeps the ratchet meaningful in the degenerate case (it just becomes the old binary behavior).

- `python -m aura_harness.bench --task duplicate_finder --runs 1 --n 3 --critic-rounds 2 --critic-model deepseek-r1:14b` runs to completion.
- The session's `batches/batch-000.jsonl` shows `tests_passed`, `tests_total`, `failures`, and `ratchet_accepted` on every round.
- The session's `summary.json` shows `mean_tests_passed` and `mean_tests_total`.
- A retry that scores worse than prior-best appears in the rounds list with `ratchet_accepted: false` and does NOT influence the next round's prompt.
- Existing tests still pass. Add tests if you find yourself touching code paths that have tests already covering them; don't add new test files.
