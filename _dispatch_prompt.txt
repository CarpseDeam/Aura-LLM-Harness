Goal: extend the Backend contract with chat_stream(), implement it on LocalOllamaBackend additively, add CloudHTTPBackend using the openai SDK pointed at DeepSeek's OpenAI-compatible endpoint. End state: both backends satisfy the extended Protocol; the cloud backend is independently runnable via a smoke CLI before any station wiring.

StreamChunk

Add a frozen dataclass StreamChunk in backend/protocol.py alongside CompletionResult:
- delta: str — incremental text for this chunk; "" allowed
- final: CompletionResult | None — None during streaming, populated on the terminal chunk with the full accumulated CompletionResult

The terminal chunk may carry both delta and final, or final with delta="" — either shape is fine. Caller pattern is "iterate chunks, accumulate or display deltas, capture final when chunk.final is not None."

Backend Protocol: add chat_stream

Same kwargs as chat(), returns Iterator[StreamChunk]:

chat_stream(messages, *, model, temperature=0.2, seed=None, max_tokens=None, response_format=None, reasoning=False) -> Iterator[StreamChunk]

Semantic contract between the two methods: consuming chat_stream() to completion and taking chunk.final must produce a CompletionResult equivalent to calling chat() with the same args. Implementations are free to share code or not; the contract is what matters.

LocalOllamaBackend.chat_stream

Hits Ollama's /api/chat with stream=true. Each JSON line in the response becomes StreamChunk(delta=msg.content, final=None). The line with done=true builds CompletionResult from total_duration, prompt_eval_count, eval_count, raw, and yields StreamChunk(delta="", final=result).

Leave LocalOllamaBackend.chat() alone. Its current non-streaming /api/chat path is what dispatch 3's regression check ran against; don't reroute it through chat_stream(). chat_stream is purely additive.

backend/cloud_http.py — new file

CloudHTTPBackend class. Constructor:
- base_url: str
- api_key: str
- name: str = "cloud"
- timeout: float = 900.0 (DeepSeek can hold connections open during queueing; default openai timeout of 600s is borderline)

Stores an openai.OpenAI client built from base_url, api_key, timeout. Exposes self.name for genealogy.

Implements both:
- chat(messages, *, model, ...) -> CompletionResult: client.chat.completions.create(stream=False, ...), shape the response into CompletionResult. response_format passes through to the SDK (DeepSeek supports {"type": "json_object"}). reasoning=True maps to DeepSeek's thinking mode parameter — verify the exact name from current docs. temperature, seed, max_tokens are standard OpenAI params.
- chat_stream(messages, *, model, ...) -> Iterator[StreamChunk]: client.chat.completions.create(stream=True, stream_options={"include_usage": True}, ...). Iterate chunks, yield StreamChunk(delta=chunk.choices[0].delta.content or "", final=None). On the final chunk (finish_reason set, usage block populated), accumulate the full text from prior deltas and yield StreamChunk(delta="", final=CompletionResult(...)) using the usage block for token counts.

DeepSeek's keep-alive/empty SSE events are handled transparently by the openai SDK iterator — no special filtering needed.

Errors: catch openai.APIError and its subclasses, re-raise as BackendError (the existing unified type from dispatch 1) preserving the original message and status.

backend/cloud_constants.py — DeepSeek defaults

A small module exposing:
- DEEPSEEK_BASE_URL = "https://api.deepseek.com"
- Optionally model name constants (DEEPSEEK_FLASH, DEEPSEEK_PRO) — nice but not required; strings are fine.

Future cloud providers (Anthropic, Together, OpenRouter, etc.) will get their own constants files using the same CloudHTTPBackend class.

Dependency

Add openai to pyproject.toml (or requirements.txt). Pin to a recent stable version. Run install if needed.

Smoke CLI

backend/smoke.py with a __main__ block. Args:
- --backend {local,cloud}
- --model <model_name>
- --prompt <text>
- --stream / no flag for non-streaming
- --reasoning / no flag

For --backend cloud: read DEEPSEEK_API_KEY from env, construct CloudHTTPBackend with DEEPSEEK_BASE_URL.
For --backend local: construct LocalOllamaBackend with default URL.

With --stream: iterate chat_stream(), print deltas as they arrive (no buffering — flush on each delta), print the final CompletionResult's token counts and duration at the end.
Without --stream: call chat(), print result text, then token counts and duration.

This is the verification path. User will run it against both backends to confirm cloud auth, streaming, keep-alive tolerance, and thinking mode all work before any station wiring touches CloudHTTPBackend.
