aura_harness/stations/

New module. Files:

base.py — Station abstract base class. Required attributes: `name: str`, `backend: Backend`. Provides one helper, `_genealogy(seed=None, input_ref=None) -> dict` that returns the five genealogy fields (produced_by_station=self.name, produced_by_backend=self.backend.name, produced_at=<timestamp in whatever format types.py uses — match the existing convention, str-ISO or datetime — don't introduce a new one>, seed=seed, input_ref=input_ref) ready to spread into a frozen dataclass constructor. No `run` method on the base — signatures vary per station, so subclasses define their own. Keep base.py minimal; it's not trying to enforce a uniform contract, it's sharing genealogy plumbing.

critic.py — CriticStation. Constructor takes name (default "critic"), backend, and a CriticClient instance (caller constructs and passes in, so model selection stays at the call site). Signature: `run(artifact: CodeArtifact, slice: Slice) -> CritiqueReport`. Calls CriticClient's single-pass critique method (the one that does one critique without looping — if CriticClient currently only exposes `run_with_critic_loop`, factor out the single-pass path as a public method on CriticClient and have run_with_critic_loop call it. Don't change run_with_critic_loop's behavior — the existing bench still uses it). Take the parsed critic output and shape it into a CritiqueReport with genealogy stamped, input_ref=artifact.id. Whatever fields CritiqueReport has in types.py, populate from the critic output.

worker.py — WorkerStation. Constructor takes name (default "worker"), backend, candidate_generator, critic_station, max_critic_rounds (int). Signature: `run(slice: Slice, state: RunState) -> CodeArtifact`. Returns the final CodeArtifact only — intermediate retry artifacts are constructed during the loop (so parent_artifact_ids on later rounds can reference the prior id) but not returned or stored in state. This matches existing CriticClient.run_with_critic_loop semantics; if a future dispatch needs the full chain accessible (plan-level critic reconstructing genealogy), we'll change the return shape then. Don't paint into a corner that prevents that — the intermediate artifacts should be real CodeArtifact instances with real ids, just discarded after the loop.

Internal flow inside run():
1. Generate k candidates via candidate_generator. k comes from the generator's existing config or a constructor param — match existing behavior.
2. Validate candidates (AST parse, expected_symbols presence per slice.contract.expected_symbols, forbidden_imports check per slice.contract.forbidden_imports). If validation logic currently lives inside CandidateGenerator, reuse it; if it lives elsewhere, call it from there. Don't reimplement.
3. Pick the best valid candidate using existing selection logic.
4. Build CodeArtifact (round 0): parent_artifact_ids=(), genealogy stamped with input_ref=slice.id and seed=<whatever seed was used, None if unseeded>.
5. Loop up to max_critic_rounds:
   - critic_station.run(current_artifact, slice) → CritiqueReport.
   - If report indicates pass (whatever the schema's pass-flag is — match types.py), return current_artifact.
   - Else, regenerate candidates with reflexion feedback (the existing CandidateGenerator code path that takes critique feedback as additional context — find it, reuse it).
   - Validate, pick best.
   - Build new CodeArtifact: parent_artifact_ids=(prior.id,), genealogy stamped.
6. After loop exhaustion, return the last artifact built (even if its critique didn't pass).

The validation step and the candidate-picking step exist in CandidateGenerator already. Don't duplicate the logic in WorkerStation — call the existing methods. WorkerStation is a thin orchestrator over CandidateGenerator and CriticStation, not a reimplementation.

__init__.py — exports Station, WorkerStation, CriticStation.

aura_harness/pipeline/

New module. Files:

linear.py — LinearExecutor. Constructor takes worker_station and optionally an integrator_station (None for now; if non-None, called after the slice loop completes — leave the wiring as a single-line call site with a TODO, don't implement IntegratorStation in this dispatch). Signature: `run(state: RunState, plan: Plan) -> RunState`. Iterates plan.slices in input order (no topo-sort yet — duplicate_finder is single-slice, and Slice may not even have a depends_on field; if it does, leave the topo-sort as TODO). For each slice, calls worker_station.run(slice, state), and returns a new RunState with the resulting CodeArtifact appended to state.code_artifacts (or whatever the schema field is called for the artifact tuple). Immutable: `RunState(..., code_artifacts=state.code_artifacts + (artifact,))`.

__init__.py — exports LinearExecutor.

__main__.py — CLI entrypoint. Mirrors the existing bench CLI: `python -m aura_harness.pipeline --task duplicate_finder --runs 3 --n 3 --model qwen2.5-coder:7b --critic-rounds 2`. Loads the same task definition the bench loads (same task registry / loader). For each run: builds a TaskSpec, builds a Plan with the task's single Slice, constructs LocalOllamaBackend, CandidateGenerator, CriticClient, CriticStation, WorkerStation (with max_critic_rounds from the CLI), LinearExecutor. Runs the executor, extracts the resulting CodeArtifact, scores it using the existing bench scoring function (find it, import it, reuse it). Prints per-run scores and aggregate. Output format should be close enough to the bench's that user can eyeball-compare. This entrypoint is the regression check: same task, same model, same k, same critic-rounds → score within noise of the existing bench's historical 70-80% range for qwen2.5-coder:7b on duplicate_finder.

Behavior details:
- Genealogy on CodeArtifact: produced_by_station = "worker", produced_by_backend = "local_ollama", produced_at populated, seed = whatever the candidate generator used (None if unseeded), input_ref = slice.id.
- Genealogy on CritiqueReport: produced_by_station = "critic", produced_by_backend = "local_ollama", produced_at populated, seed = None, input_ref = artifact.id.
- parent_artifact_ids: () on round 0, (prior.id,) on retries. This is a tuple even with one element.
- All schema dataclasses are frozen — construct them at the end, don't try to mutate. RunState updates are "build new RunState with extended tuples."
