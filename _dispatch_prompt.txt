## Spec: Critic + reflexion loop for the bench

Add a critic that reviews each candidate against the task spec and produces a structured critique, plus a reflexion loop in the bench runner that feeds critiques back to retry failed candidates. This is the core architecture move — local model + small coder + critic + retry should beat one-shot generation. Bench is the venue we measure it in.

**File layout:**

`src/aura_harness/critic/__init__.py` — package exports.

`src/aura_harness/critic/models.py` — Frozen dataclasses for the structured critique output. At minimum: a `Critique` type with a boolean indicating whether the candidate passes review, a tuple of violation strings (concrete, mechanical contract issues — "function `find_duplicates` is not at module level", "code calls `.as_posix()` on a string instead of a Path"), and a tuple of suggestion strings (terse fixes — "use `Path(p).relative_to(directory).as_posix()`"). Keep the type small and serializable.

`src/aura_harness/critic/critic_client.py` — Stateless service mirroring the shape of `PlannerClient` and `OllamaClient`. Public method takes the spec text and the candidate's raw code, calls the reasoning model via `OllamaClient.chat`, and returns a `Critique`. Default model is a `Final[str]` constant — pick `deepseek-r1:14b` since the user has it. The system prompt frames the model as a code reviewer: read the spec, read the candidate, find concrete contract violations, output structured JSON. Strongly prompt for JSON-only output and parse with a tolerant extractor (look for the first `{...}` block, fall back to error). On parse failure, return a `Critique` with `passed=False` and a single violation string explaining the parse error — never raise. Log critic calls to `.aura/critic.jsonl` mirroring the existing logging pattern.

`src/aura_harness/bench/runner.py` — Extend the existing runner with reflexion. Add a new optional parameter to `run_bench` for the maximum number of critic rounds (default 0 = current behavior, no critic). When `max_rounds > 0`: after a candidate fails verification, call the critic on the candidate's code + spec. If the critic produces violations, construct a follow-up prompt that includes the original spec, the candidate's code, the critique's violations and suggestions, and a clear instruction to produce a corrected version. Send that follow-up to the existing `CandidateGenerator` for ONE candidate (not N) and re-verify. Repeat up to `max_rounds` times. Each round's candidate is logged separately. The final pass/fail for that candidate slot is whichever round (if any) passed. Keep the original candidate's seed for reproducibility; new rounds get fresh seeds.

`src/aura_harness/bench/models.py` — Extend `CandidateResult` (or add a sibling type) so each round of reflexion is captured: round index, the critique that triggered the retry, the new candidate's code, pass/fail. Existing single-shot results are round 0 with no critique.

`src/aura_harness/bench/__main__.py` — Add `--critic-rounds <int>` CLI flag (default 0). When > 0, the runner invokes the critic loop. Add `--critic-model <name>` (default `deepseek-r1:14b`) so the user can swap reasoning models without code changes.

`src/aura_harness/bench/session.py` — Update batch JSONL and results.json to capture the per-round detail. Summary should report both the one-shot pass rate (round 0 only) and the final pass rate (any round passed) so the critic's contribution is legible at a glance.

**Conventions:**

`from __future__ import annotations` everywhere. Type hints throughout. Frozen dataclasses for structured types. `Final[...]` for the critic model name, max parse attempts, default round count, and any prompt-related constants. Mirror existing idioms from `planner/`, `lab/`, `scoring/`, `bench/`. The critic is fully separate from the existing pipeline — `lab/` and `scoring/` should not import from `critic/`. The bench runner is the only consumer.

**Definition of done:**

`python -m aura_harness.bench --task duplicate_finder --runs 5 --n 5 --critic-rounds 2` runs the full reflexion loop. Session output captures every round of every candidate with its critique. Summary reports one-shot pass rate vs final pass rate. Existing `--critic-rounds 0` behavior is identical to today's runner. Critic JSONL logs every call.

Be methodical. Read what you need, make the change, stop. Match existing code style. Type hints everywhere.
