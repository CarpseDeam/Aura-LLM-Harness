## Spec: Workspace, file context, apply candidate

The harness can generate but can't (a) feed existing files into the prompt as context, or (b) write a chosen candidate to disk. This makes it useless as a real coding tool. This dispatch fixes both.

### Workspace concept

New module `src/aura_harness/workspace/`:
- `manager.py` — `WorkspaceManager` class
- `__init__.py` — re-exports
- New `WorkspaceError` exception (in `manager.py` is fine, no need for a separate file)

WorkspaceManager API:
- `__init__(self, root: Path)` — set root, create dir if missing
- `root` property → current root
- `set_root(self, root: Path) -> None` — change active root, create if missing
- `list_files(self) -> list[Path]` — recursive, returns paths relative to root. Skip: dotfiles, dotdirs, `__pycache__`, `.venv`, `.git`, `node_modules`. Sort alphabetically.
- `read_file(self, rel_path: Path) -> str` — UTF-8 text read. Raise `WorkspaceError` if the resolved path escapes root.
- `write_file(self, rel_path: Path, content: str) -> None` — UTF-8 text write, create parent dirs. Same escape check.

All path operations must resolve and verify `is_relative_to(root)` to prevent escape via `..` or absolute paths.

Default workspace path: `<project_root>/workspace/`. Create on first launch with a simple `README.md` inside saying "Aura LLM Harness workspace" so the tree isn't empty.

### GUI changes

MainWindow constructor changes from `MainWindow(client, generator)` to `MainWindow(client, generator, workspace)`. Update `__main__.py` accordingly: construct WorkspaceManager pointing at `./workspace` and pass it in.

Layout change: split the main window into a left sidebar (~250px wide) and a right column (everything that's currently there).

Sidebar contents:
- A small header row: `QLabel("Workspace:")` + a `QLabel` showing the current root path (truncate with elision if long) + a small `[...]` button. Clicking the button opens a directory picker; chosen directory becomes the new workspace root.
- A `QListWidget` showing files from `workspace.list_files()`. Each item has a checkbox via `Qt.ItemFlag.ItemIsUserCheckable`. Checked items are "context files."
- A "Refresh" button below the list that re-runs `list_files()`.

Right column: keep the existing layout (output, validation group, input, controls).

### Submit flow with context

When the user clicks Send, before constructing the BatchWorker:
- Walk the file list widget, collect the relative paths of all checked items.
- For each path: try `workspace.read_file(path)`. If the file is over 100KB, skip it and `logger.warning("skipping %s (>100KB)")`. If it raises, skip and warn.
- If any context files were collected, build the final prompt as:
  ```
  # File: <relpath1>
  <contents1>

  # File: <relpath2>
  <contents2>

  ---

  <user prompt>
  ```
  Use a single divider line of `---` between context and the user's prompt.
- Pass that combined string as the prompt to the BatchWorker.
- Also append a muted line to the output area noting how many context files were attached, e.g. `"Attaching 2 file(s) as context."`

### Apply candidate

Each rendered candidate (both unscored and scored paths) gets an "Apply" button. Place it as part of the per-candidate render block — a small `QPushButton` after the status line, before the code block. (You can either embed the button into the QTextEdit via `QTextDocument` insertion which is awkward, OR — simpler — use a different rendering approach for candidates: insert each candidate as a small `QFrame` or widget into a vertical layout in a scrollable area that replaces the QTextEdit. Pick whichever is cleaner; if going with the QTextEdit approach is genuinely too painful for buttons, switch to a `QScrollArea` with a `QVBoxLayout` of candidate widgets.)

Clicking Apply on a candidate:
- Determine "code to write": if the candidate has extracted code (scored path), use that. Otherwise use the raw candidate text. If the candidate failed entirely (model error), the Apply button should be hidden or disabled.
- Open `QFileDialog.getSaveFileName(self, "Apply candidate", str(workspace.root), "Python files (*.py);;All files (*)")`. Default the filename to something like `candidate.py`.
- If the user cancels: do nothing.
- If the chosen path is outside the workspace root: show a `QMessageBox.warning` with "Files must be saved inside the workspace." and abort.
- Otherwise, compute the relative path, call `workspace.write_file(rel, code)`, then refresh the file list.
- Append a muted line confirming: `"Wrote candidate [i] to <relpath>"`.

### Notes

- The output area refactor (if you go the QScrollArea route to host buttons) means existing render methods need to produce widgets instead of HTML strings. This is fine — make a `_make_candidate_widget(...)` and `_make_scored_widget(...)` that return a styled QWidget per candidate. The header line / muted lines can still be QLabel widgets.
- Workspace root doesn't need to persist across launches yet.
- No syntax highlighting needed.

### Standards
Type hints, module loggers, no new third-party deps, no new tests for this dispatch.

### Definition of done
- App opens with sidebar showing the contents of `./workspace/` (will at least show `README.md`)
- Clicking `[...]` lets you switch workspaces; tree refreshes
- Checking files and submitting injects them into the prompt — verify by inspecting `.aura/calls.jsonl`, the prompt should contain `# File: ...` headers
- Each rendered candidate has an Apply button that opens a save dialog and writes the code; tree refreshes after
- Outside-workspace paths get rejected with a clear message
- The existing unscored and scored paths still render correctly

Be methodical. Read what you need, make the change, stop. Match existing code style. Type hints everywhere.
