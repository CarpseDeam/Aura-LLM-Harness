## Goal
Right now `python -m aura_harness.bench` prints the session path and then nothing until it finishes. For long runs (45-90 min) this gives the user no way to tell if it's progressing or stuck. Add stdout progress logging and a `progress.json` file in the session directory.

## Stdout progress
Print to stdout on these events, in `bench/runner.py`:

- Run start: `[run 1/5] starting batch generation...`
- Round 0 candidate complete: `[run 1/5 cand 3/5] round 0: 7/9 tests passed (12.4s)`
- Critic call: `[run 1/5 cand 3/5] critic round 1...` and on completion `[run 1/5 cand 3/5] critic round 1 done (28.1s, 3 violations)`
- Retry generation: `[run 1/5 cand 3/5] retry round 1...` and on completion `[run 1/5 cand 3/5] retry round 1: 8/9 tests passed (RATCHET) (31.2s)` or `[run 1/5 cand 3/5] retry round 1: 5/9 tests passed (rejected) (29.7s)`
- Model unload: `[unload] qwen2.5-coder:7b` (these are noisy — gate behind a `--verbose` flag, default off)
- Run complete: `[run 1/5] complete: 4/5 passed in 14m21s`
- Session complete: `[done] 18/25 passed (72%) in 47m12s, written to <session_dir>`

Format is freeform but use the `[run X/Y cand A/B]` prefix consistently so the user can grep/filter.

Use `print(..., flush=True)` so output appears immediately under buffering (Windows console is particularly bad about this).

## progress.json
The runner writes/overwrites `<session_dir>/progress.json` on every meaningful event. Schema:

```json
{
  "status": "running" | "complete" | "error",
  "started_at": "<iso8601>",
  "elapsed_seconds": 1247.3,
  "current_run": 2,
  "total_runs": 5,
  "current_candidate": 3,
  "candidates_per_run": 5,
  "current_round": 1,
  "current_phase": "generating" | "critiquing" | "retrying" | "verifying" | "idle",
  "passes_so_far": 7,
  "candidates_completed": 12,
  "total_candidates": 25,
  "ratchets_accepted": 4,
  "ratchets_rejected": 3,
  "last_event": "retry round 1: 8/9 tests passed (RATCHET)"
}
```

Doesn't have to be atomic-write-perfect — best-effort overwrite is fine. If a write fails, log the error and continue (progress is observability, not correctness).

Update on these events: every candidate completion, every round transition, every critic/retry phase boundary. A few writes per second at peak is fine.

On run completion or exception, set `status` to `complete` or `error` and stop updating.

## Where this goes
- `src/aura_harness/bench/runner.py` — the print statements and progress.json writes.
- Probably a small helper class `_ProgressTracker` in the same file that owns the counters and the json path. Keep it private to runner.py; no need for a separate module.
- Add `--verbose` flag to `bench/__main__.py` to enable the noisy unload prints.

## Definition of done
- A long bench run produces continuous stdout output.
- `<session_dir>/progress.json` exists and updates during the run.
- After completion, `progress.json` shows `status: "complete"` and the final stats.
- All 68 existing tests still pass.

## Out of scope
- Any UI work. This is stdout + json file only.
- A separate watch/tail tool. We'll discuss that as a UX question.
- Restructuring the bench pipeline (batch-mode generation, etc.) — separate dispatch.
- Changing the JSONL session format — leave that alone.

Be methodical. Read what you need, make the change, stop. Match existing code style. Type hints everywhere.
